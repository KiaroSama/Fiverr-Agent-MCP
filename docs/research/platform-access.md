# Platform access review

Reviewed 2026-10-11. This project is unofficial and is not a hosted Fiverr service.

## Verified boundaries

[Fiverr Terms of Service](https://www.fiverr.com/legal-portal/legal-terms/terms-of-service), displayed January 2026, section 8.8 restrict unauthorized third-party modification, protection circumvention, automatic collection/scraping and systematic retrieval. A user's own account session does not itself establish Fiverr permission for automation. The application must never solve CAPTCHA, rotate fingerprints/proxies, bypass a challenge or manufacture an API.

No public comprehensive official Fiverr account API/OAuth/MCP contract was verified in the reviewed official pages and bounded GitHub searches. This does not prove that private partner arrangements do not exist. Account automation requires a documented permitted interface and account entitlement; account authentication and platform permission are separate checks.

The owner requests account-backed operation through manual login, not a local-only replacement. Local work remains usable while real-account adapters are experimental, permission-gated or manual-only. Fixture verification is never live verification. Account identity must come from account-scoped evidence; an HTTP success or page title is insufficient.

## Mira and historical Briefs

[Official Briefs replacement notice](https://help.fiverr.com/hc/en-us/articles/4415601609361-Post-a-project-brief-get-tailored-offers-for-your-project) says Mira fully replaced new Briefs, while old records remain accessible temporarily. [Mira documentation](https://help.fiverr.com/hc/en-us/articles/48756531483537-Finding-talent-with-Mira) describes seller opportunities as distinct Inbox threads and account-dependent rollout. There is no verified universal project-search or buyer-directory API. Exact deadlines, inferred reminders and unknown times must be distinguished.

## Account risks

The human handles sign-in, MFA, CAPTCHA, identity checks and contractual/financial actions. [Official identity-verification guidance](https://help.fiverr.com/hc/en-us/articles/6348992414097-Verifying-your-identity-as-a-new-freelancer) advises disabling proxies/VPN for verification; this application must not silently switch routes. Such verification is a separate owner-controlled official-site handoff.

[Community Standards](https://help.fiverr.com/hc/en-us/articles/32242973123985-Our-Community-Standards) prohibit unsolicited promotion/mass messaging and manipulated reviews/identity. No collection of client leads, fake hours, review fabrication or automatic payments is a capability.

## Reference assessment

- KyuRish/fiverr-mcp-server: observed public-page Perseus extraction, not an official seller API; impersonation/403 retries rejected.
- marwankous/fiverr-mcp: logged-in browser DOM/native messaging, not an approved account contract; arbitrary JavaScript and unauthenticated bridge rejected.
- eaglecheow/mcp-fiverr: heuristic legacy Briefs endpoint attempts and cookie-header reuse; not current Mira evidence, and no LICENSE grant file in inspected tree.
- Ahad690/fiverr-gig-optimizer: useful local deterministic numeric helpers. MIT code and CC-BY-4.0 documentation/data are kept separate; conflicting MIT instruction metadata is recorded, not silently preferred.

Public official documents, source/manifests/licenses and selected tests were inspected. No live account, private data, browser account mutation, message, order delivery or financial operation was exercised. Wider partner discovery and full auxiliary-reference audits remain incomplete; no full live readiness claim is made.
