# Privacy and file policy

The installation owns .state/, .cache/, logs/, exports/ and config/. Sensitive browser profiles/settings/database/token files are never shipped. Root resolution is independent of caller CWD. TEMP/TMP/TMPDIR/XDG_CACHE_HOME are set on an early same-executable child/replacement before runtime initialization, not through unsafe concurrent environment mutation.

Cookie-session credentials reside in a separate private SQLite database under `.state/browser`, not the workspace database; workspace backup/export does not include the raw cookie. Import accepts only a bounded installation-local private file and never model tool arguments or a cookie command-line value. Status/logs expose no credential. Extension mode does not export browser cookies. Forget clears app-held credentials/observations, not the original input file or remote/browser session; SQLite secure deletion is not forensic SSD/backup erasure. This storage uses filesystem protection, not application-level encryption. See [authentication](authentication.md).

Unix private directories/files use0700/0600. Windows resets explicit grants, removes inherited grants and grants the selected owner through bounded icacls operations before sensitive writes; failure stops storage initialization. Native Windows CI checks protected, current-token-owner-only DACLs on a freshly created workspace, database and log directory (run38352515372). This is bounded fixture evidence, not universal ACL or owner-identity assurance. This does not prove protection from an administrator, hostile process environment, malicious owner, filesystem race attacks or backups/sync performed outside the app. Native tests must validate actual permissions.

Relative file policy refuses absolute/UNC/ADS/device/traversal/dot/empty components, symlink/reparse ancestors and physical escapes. Exports use create-new, bounded data and SHA256; never overwrite inputs. Export suffixes must match the chosen format: JSON `.json`, CSV `.csv`, Markdown `.md`/`.markdown`, and HTML `.html`/`.htm` (case-insensitive). A mismatched suffix is rejected before any export is written. CSV strings are quoted and formula-prefixed; HTML is escaped with restrictive CSP. Markdown payloads are literal JSON code blocks with fences longer than any payload backtick run, not interpreted links, images or HTML. Files remain untrusted even when escaped; a local record cannot grant permission or execute attachment instructions.

Prepared file bindings allow only explicit root-owned bounded UTF-8 text, signature-checked PDF/PNG/JPEG; hashes/sizes and draft version are checked before approval/commit. This is not a malware scanner or remote upload: active web formats/executables/archives are refused, and PDFs must still be reviewed independently. Binding does not authorize arbitrary path access.

SQLite uses immediate transactions, busy timeout, full synchronization, versioned schema, scoped records and revision history. Failed/conflicting import rolls back; corrupt/newer storage is never automatically reset. Backups contain private settings/account data and must remain private. Backup validation and empty-workspace restore check integrity/schema/row bindings; old approvals/tokens cannot regain authority. Records retain 100 prior revisions. Existing snapshots cannot be replaced through the service or storage save API, even with a matching version. To capture changed evidence, create a new snapshot. This is application-level immutability, not protection from an owner editing the database outside the application. New record/import/action writes are capacity-checked transactionally (10,000 rows per data table and 48 MiB aggregate JSON); failed capacity checks roll back. Database repair, full disk-byte quotas, arbitrary filesystem races and complete retention management remain outside the verified scope.

Logs are UTF-8 UTC structured files, unique per run, bounded per file, no bridge stdout contamination. Redaction applies before formatting, including nested sensitive field names and credential URLs. Default messages omit private bodies. Do not publish logs without review/redaction; metadata inspection is safer. Retention must not delete an actively locked log. Cache cleanup currently defaults to dry-run and refuses recursive apply until worker quiescence can be proved. Preserving data is preferred to pretending cleanup succeeded.

Direct Store imports apply the same per-record 256 KiB object bound as save/restore; batch validation occurs before writes so oversized rows cannot break later recovery. The expanded negative fixtures do not certify arbitrary filesystem races.
